hive-skills · reference

The planning pipeline

Five sequential stages take a repo from no plan to a reviewed, ticketed breakdown ready to build. Two stages pull in supporting skills mid-step; one skill runs underneath all of them.

Self-driving handoff — verified, not assumed

Nothing external routes this pipeline. Every stage's own file names what to run next, in its own words, at the end of its run:

hive-architect

"Offer /hive-spec-writer to turn the outcome into a spec. Also mention optional /hive-panel."

hive-spec-writer

Offers a branch, not a single next step: run /hive-panel over the spec now while it's cheap to change, or go straight to /hive-issue-planner.

hive-issue-planner

"After publishing, offer /hive-walkthrough — the comprehension gate whose sign-off is /hive-master's go-signal."

hive-walkthrough

Doesn't offer — it gates. Only an unambiguous human sign-off unlocks the next step (/hive-master, build — outside this repo).

hive-profile-builder

The one exception — no self-narrated handoff. The pointer to architect lives one level up, in the PROJECT-PROFILE.md it writes.

Pipeline stages — run in order

01hive-profile-builder

Scans a repo once and writes PROJECT-PROFILE.md — a one-screen router recording docs, commands, tracker conventions, and review lenses. Every later stage reads this instead of re-discovering the repo.

02hive-architect

The grill. A relentless interview that sharpens a plan or design, writing ADRs and glossary terms as decisions land, pulling in options and a cross-model check along the way.

03hive-spec-writer

No new interview — synthesizes the conversation the grill just sharpened into a spec/PRD and publishes it to the tracker.

04hive-issue-planner

Breaks the spec into tracer-bullet tickets, each with blocking edges, acceptance criteria, and a Verification DOD — the actual Jira/Linear/GitHub issue bodies.

05hive-walkthrough

The last gate before code. Briefs the human top-down — whole thing, then phases, then tickets — in plain language, so nothing gets built as a surprise.

Called on demand — not fixed steps

hive-ideate

Call it when: the plan is high-stakes and the obvious first answer might be wrong — architecture, a public surface, a schema, a phase about to ship — before the grill starts. Generates real alternatives (isolated parallel "frames," critic-scored) so architect grills the survivors instead of a single cold plan.
Not wired in: architect's own file never mentions it. Today a human has to run /hive-ideate first and hand its output in — the automatic hand-off is an open TODO in ideate's own file.

hive-second-opinion

Call it when: architect hits a major solution-path fork — an approach choice, not a clarifying question. Architect's own file triggers this directly and surfaces the result before you decide; agree → one recommendation, disagree → one debate round then converge.

hive-panel

Call it when: issue-planner's step 5 finds the spec carries a real "Ownership and invariants" section, or the scope touches security/isolation or a destructive migration (those two lenses always run when relevant). Heavy adversarial review — lens panel plus advocate/skeptic debate — over the spec + breakdown, scoped to just what the invariant trace flagged as uncovered or contradictory. Skipped when the ADR behind the ticket already passed its own review — re-litigating a settled decision just pays for the privilege.

Runs continuously inside a stage

domain-modeling

Not situational — architect calls it every time a decision actually settles, recording the ADR and glossary term right then. Keeps the plan's vocabulary pinned down so a term means one thing for the rest of the pipeline.

hive-report

Used in every human-facing stage but one — architect, spec-writer, issue-planner, and walkthrough all address you "per /hive-report" by name in their own files. Not a stage itself: the shared voice and formatting rules that keep those four from drifting into their own style. (profile-builder doesn't cite it — it mostly writes a repo-facing file, not a human-facing report.)

grilling

The generic interview mechanic hive-architect forks from — the question discipline itself, reusable outside hive entirely.
